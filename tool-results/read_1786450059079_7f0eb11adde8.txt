     4→// the datasource provider; row-level security can then be added in a migration.

  1305→// ============================================================================
  1306→//  PAYMENT INVOICES (NowPayments crypto + Stripe card)
  1307→// ============================================================================
  1308→//
  1309→// SECURITY MODEL — strict payment security rules:
  1310→//
  1311→//   1. ZERO CLIENT TRUST: the client never sends a price. It sends only
  1312→//      { plan, billingCycle, idempotencyKey }. The server reads the price
  1313→//      from PLAN_PRICES_USD (server-side table) and writes `amountUsd`
  1314→//      to the invoice row. The client cannot tamper with the amount.
  1315→//
  1316→//   2. IDEMPOTENCY: `idempotencyKey` is a client-supplied UUID with a
  1317→//      UNIQUE constraint. If the client retries (network blip), the
  1318→//      server returns the existing invoice instead of creating a new one.
  1319→//      The unique constraint is enforced at the DB layer — race-safe.
  1320→//
  1321→//   3. WEBHOOK VERIFICATION: every webhook is verified via HMAC-SHA512
  1322→//      signature (NowPayments) or HMAC-SHA256 (Stripe) computed over the
  1323→//      RAW body. The signature secret is in NOWPAYMENTS_IPN_SECRET /
  1324→//      STRIPE_WEBHOOK_SECRET. Webhooks failing verification are dropped.
  1325→//
  1326→//   4. WEBHOOK-ONLY BUSINESS LOGIC: subscription activation runs ONLY in
  1327→//      the webhook handler. The /api/billing/return endpoint is DISPLAY
  1328→//      ONLY — it fetches invoice status for the UI but never mutates the
  1329→//      subscription. This prevents return-URL tampering (e.g. an attacker
  1330→//      crafting `/api/billing/return?invoice_id=xxx&status=confirmed`).
  1331→//
  1332→//   5. REPLAY PROTECTION: `processedWebhooks` stores the IDs of every
  1333→//      webhook event already processed. Duplicate deliveries (NowPayments
  1334→//      retries on 5xx) are a no-op — the status is already terminal.
  1335→//
  1336→//   6. ATOMIC STATUS TRANSITIONS: status changes use `updateMany WHERE
  1337→//      status IN (allowed_prev_states)` so two concurrent webhooks
  1338→//      cannot both transition the invoice. Only one wins; the other gets
  1339→//      count=0 and is a no-op.
  1340→//
  1341→//   7. UNDERPAYMENT PROTECTION: the webhook only transitions to
  1342→//      `confirmed` when `amountReceivedCrypto >= amountDueCrypto`. Partial
  1343→//      payments stay in `confirming` until the full amount arrives or the
  1344→//      invoice expires.
  1345→//
  1346→//   8. CRON RECONCILIATION: an hourly cron queries the NowPayments API
  1347→//      for every `pending`/`waiting`/`confirming` invoice and syncs the
  1348→//      status — catches missed webhooks (network outages, endpoint down).
  1349→//
  1350→//   9. INVOICE EXPIRY: crypto invoices expire (typically 20 min). The
  1351→//      cron marks expired invoices as `expired` and never activates the
  1352→//      subscription.
  1353→//
  1354→//  10. REFUND SAFETY: refunds require platform-admin + step-up auth and
  1355→//      are NEVER automatic. The `refunded` status is terminal.
  1356→//
  1357→//  11. AUDIT TRAIL: every status change is recorded as an audit event
  1358→//      with the actor (user/system/webhook/provider).
  1359→
  1360→model PaymentInvoice {
  1361→  id              String   @id @default(cuid())
  1362→  tenantId        String
  1363→  userId          String // who initiated the checkout
  1364→
  1365→  // Provider fields
  1366→  provider        String   // 'nowpayments' | 'stripe'
  1367→  providerInvoiceId String? // NowPayments invoice_id or Stripe session_id
  1368→  providerPaymentId  String? // NowPayments payment_id (set when payment detected)
  1369→
  1370→  // What was purchased — SERVER-AUTHORITATIVE (zero client trust)
  1371→  plan            String   // trial | starter | business | enterprise
  1372→  billingCycle    String   // 'monthly' | 'annual'
  1373→  seats           Int
  1374→  storageBytes    BigInt
  1375→  amountUsd       Float    // server-calculated price in USD (from PLAN_PRICES_USD)
  1376→  amountDueCrypto Float?   // crypto amount due (set by NowPayments)
