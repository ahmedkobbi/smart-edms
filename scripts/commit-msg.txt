Phase C part 1 — Alert routing config.

## Notification routing

**Gap:** Severity was set per-notification but there was no admin UI to
configure routing rules (e.g. "critical → email + Slack; warning →
in-app only"). The master prompt §9.13 requires "alert severity and
routing must be configurable."

**Implemented:**
- New `NotificationRouting` Prisma model:
  - `minSeverity` (info | success | warning | critical) — minimum
    severity to trigger the route
  - `typePattern` (e.g. `security.*`, `workflow.*`, `*`) — glob match
    on notification type
  - `channels` (JSON array: in_app, email, webhook) — delivery methods
  - `targetRoles` (JSON array of role names) — who receives; empty =
    original recipient
  - `priority` (0-1000, higher = evaluated first)
  - `enabled` boolean
- New API routes:
  - `GET /api/admin/notification-routing` — list all rules
  - `POST /api/admin/notification-routing` — create (step-up + audit)
  - `PATCH /api/admin/notification-routing/:id` — update (step-up + audit)
  - `DELETE /api/admin/notification-routing/:id` — delete (step-up + audit)
- New admin UI page at `/admin/notification-routing`:
  - Create dialog with severity selector, type pattern, channel toggles
    (in-app / email / webhook), target-roles input, priority
  - Per-rule badges showing severity, type pattern, channels, target roles
  - Enable/Disable toggle + Delete button per rule
  - Empty state with explanatory text
  - Added to sidebar navigation under Administration
- i18n key `admin.notificationRouting` added to all 5 locales
