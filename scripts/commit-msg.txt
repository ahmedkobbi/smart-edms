fix(C1-C9): patch all critical penetration test vulnerabilities

Patched all 9 critical vulnerabilities + 2 high-severity findings from the
black-hat penetration test report.

## C1 — Break-glass privilege escalation (CRITICAL)
- Added `requiredPermission: ADMIN_VIEW` + `requireStepUp: true` to the
  POST handler — any authenticated user can no longer request break-glass
- Token is now hashed (SHA-256) and stored as `tokenHash`; verified with
  `timingSafeEqualStr` in `getBreakGlassContext()` — arbitrary token values
  no longer activate the elevation
- Break-glass is created in `approved: false` state (dual-control) — a
  second admin must approve before it can be activated
- `getBreakGlassContext()` now requires `approved: true` in the DB query

## C2 — TUS path traversal (CRITICAL)
- `uploadId` validated with strict regex `^[A-Za-z0-9_-]+$` (16-128 chars)
- Secondary `path.resolve` containment check ensures resolved path is within
  the TUS data directory — blocks `../../etc/passwd` style attacks

## C3 — Redaction bypass (CRITICAL)
- Source content is now DECRYPTED before redacting (was operating on
  ciphertext, causing redaction to always fail silently)
- Redaction errors now ABORT (throw) instead of falling back to the
  original buffer — prevents creating "redacted" versions with original content
- Added checksum comparison: if `sha256(redacted) === sha256(original)`,
  the redaction is rejected as a no-op
- Added `decryptWithDek` import and IV lookup from DocumentEncryptionKey

## C4 — Cross-tenant tenant creation (CRITICAL)
- New permission `ADMIN_PLATFORM_TENANT_CREATE` ('admin:platform.tenant.create')
- Tenant creation route now requires this new permission instead of
  `ADMIN_TENANT_MANAGE` (which tenant_admin has)
- tenant_admin can no longer create new tenants — only platform admins can

## C5 — Step-up token race condition (CRITICAL)
- Replaced non-atomic check-then-set with atomic conditional update:
  `db.stepUpSession.updateMany({ where: { usedAt: null, expiresAt: { gt: now } } })`
- Only ONE concurrent request can "win" the token — others get count=0
- Eliminates the TOCTOU race window entirely

## C6 — TOTP replay (CRITICAL)
- `verifyTotp()` now returns the timestep delta (number) instead of boolean
- New `verifyTotpWithReplay()` function checks the returned timestep against
  the user's `mfaLastTimestep` — rejects if timestep <= last used
- New `mfaLastTimestep Int?` field on User model
- Auth-options login flow now uses `verifyTotpWithReplay()` and persists
  the new timestep after successful verification
- Compliant with RFC 6238 §5.2 replay protection requirement

## C7 — SSO callback SSRF (CRITICAL)
- Added `isAllowedOutboundUrl()` SSRF guard before fetching the token endpoint
- Added `isAllowedOutboundUrl()` SSRF guard before fetching the userInfo endpoint
- Blocks admin-configured URLs pointing to internal services (169.254.169.254,
  localhost, 10.x, 192.168.x, etc.)

## C8 — SAML signature forgery + JIT account takeover (CRITICAL)
- Set `wantAssertionsSigned: true` in both init and callback routes —
  unsigned SAML responses are now rejected
- Reduced `acceptedClockSkewMs` from 300000 (5 min) to 60000 (1 min) —
  closes the replay window
- Added email domain allowlist for JIT provisioning: if
  `settings.sso.allowedEmailDomains` is configured, emails from unlisted
  domains are rejected — prevents attacker-controlled IdP from creating
  accounts with arbitrary email addresses

## C9 — MFA bypass via SSO/passkey (CRITICAL)
- SSO callback: `mfaVerified` set to `false` (was `user.mfaEnabled`)
- Passkey login: `mfaVerified` set to `false` (was `user.mfaEnabled`)
- Both SSO and passkey sessions now require step-up auth for MFA-gated
  operations — the `mfaVerified` flag no longer lies about MFA status
- WebAuthn `userVerification` changed from `'preferred'` to `'required'`
  in both registration and authentication — ensures biometric/PIN verification

## Additional fixes (High severity)

### H8 — MFA pending token uses Math.random()
- Replaced `Math.random().toString(36)` with `randomBase64Url(32)` (CSPRNG)
- Eliminates token predictability

### H14 — Password reset doesn't revoke sessions
- Added `revokeAllUserSessions(user.id, 'password_reset')` after password
  update in the reset-password route — prevents attacker persistence after
  password reset

### M8 — Cron secret non-constant-time comparison
- Replaced `key !== expected` with `timingSafeEqualStr(key, expected)`
- Prevents timing-based secret extraction

## Schema changes
- `BreakGlassAccess`: added `tokenHash String?`, `approved Boolean @default(false)`,
  `approvedBy String?`, `approvedAt DateTime?`
- `User`: added `mfaLastTimestep Int?`

- Lint: 0 errors (7 a11y warnings)
