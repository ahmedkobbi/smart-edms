feat: Phase 4 — ABAC policy enforcement engine + Classification.defaultPolicy

The single largest remaining master-prompt gap: the `Policy` model and
`alertPolicyViolation()` existed but were dead code — never evaluated
during authorization. `Classification.defaultPolicy` JSON was stored but
never enforced. This commit implements a complete ABAC layer that runs
alongside the existing RBAC permission checks.

## New: src/lib/auth/policy-engine.ts

Production-grade ABAC engine with:

- **`evaluatePolicies(ctx)`** — loads tenant policies (cached 60s), filters
  by action pattern match, evaluates conditions, returns allow/deny +
  the matched policy + evaluation metadata.
- **`evaluateClassificationPolicy(defaultPolicyJson, action)`** — evaluates
  a classification's `defaultPolicy` JSON for share/download/preview actions.
- **`buildPolicyContext()`** — convenience helper for constructing the
  evaluation context from API handler fields.

### Evaluation algorithm
1. Load all enabled tenant policies (cached 60s, sorted priority DESC,
   deny before allow at equal priority).
2. Filter to policies whose `action` pattern matches (exact, prefix
   wildcard `document:*`, or full wildcard `*`).
3. For each candidate, check `resource` pattern match.
4. Evaluate `conditions` (all must match — AND logic).
5. First matching policy decides: deny → reject immediately; allow → permit.
6. No match → default allow (RBAC already gated).

### Condition matchers (15 supported)
- `classification: ['RESTRICTED', 'HS']` — document classification code in list
- `classificationMin: 3` / `classificationMax: 5` — classification level bounds
- `hasTag: 'confidential'` — document has this tag
- `hasAnyTag: [...]` / `hasAllTags: [...]` — tag set matchers
- `state: ['active', 'record']` — document state in list
- `isRecord: true` / `legalHold: true` — boolean document attributes
- `ownerOnly: true` — actor must be the document owner
- `actorRole: ['security_officer']` — actor must have one of these roles
- `timeOfDay: { start: '09:00', end: '17:00' }` — server-time window
  (supports cross-midnight windows)
- `dayOfWeek: [1,2,3,4,5]` — ISO day-of-week list (1=Mon, 7=Sun)
- `ipRange: ['10.0.0.0/8']` — CIDR matching (IPv4, with proper bit-mask math)

## Wired into createApiHandler (src/lib/api/handler.ts)

After RBAC permission check passes, the handler now evaluates ABAC policies:
- New options: `evaluatePolicies?: boolean` (default true), `policyContext?: { document? }`.
- On deny: alerts security officers via `alertPolicyViolation()`, records
  `policy.deny` audit event, returns 403 with the policy name.
- Routes that need document-specific evaluation (share/download/preview)
  call `evaluatePolicies()` manually inside the handler (the document
  isn't known until the handler runs).

## Classification.defaultPolicy enforcement

Wired into the three document-access routes:
- `POST /api/documents/:id/share` — checks `defaultPolicy.share`
- `GET /api/documents/:id/download` — checks `defaultPolicy.download`
- `GET /api/documents/:id/preview` — checks `defaultPolicy.preview`

Each route also runs full ABAC evaluation with document attributes
(classification, tags, state, isRecord, legalHold, ownerOnly).

## Policy cache invalidation

The policy admin routes (`POST /api/admin/policies`, `PATCH /api/admin/policies/:id`,
`DELETE /api/admin/policies/:id`) now call `invalidatePolicyCache(tenantId)`
after every mutation, so policy changes take effect immediately (no 60s lag).
