## نظرة عامة

**سمارت EDMS** هو منصة SaaS متكاملة لحوكمة دورة حياة الوثائق التجارية بالكامل عبر مستأجرين متعددين. يجمع النظام بين بنية أمنية مُحصَّنة (انعدام الثقة، الدفاع متعدد الطبقات، سجلات تدقيق بسلسلة تجزئة SHA-256) وتجربة مستخدم عصرية بأسلوب الزجاجية (glassmorphism) متوافقة مع الجوال أولاً.

النظام مصمَّم لدعم الضوابط المُتماشية مع **ISO 27001** و**SOC 2** و**GDPR** و**HIPAA**، ومع **القانون الجزائري رقم 18-07** المؤرخ في 10 يونيو 2018 المتعلق بحماية الأشخاص الطبيعيين في مجال معالجة المعطيات ذات الطابع الشخصي (تحت إشراف **ARPDD** — هيئة تنظيط حماية المعطيات ذات الطابع الشخصي). كما يأتي النظام بطبقة تشغيل SaaS كاملة (دورة حياة المستأجرين، تسجيل ذاتي، مزوّدا دفع مزدوجان، وحدة تحكم مشرف المنصة).

> **بيان وضعية الامتثال.** صُمِّم سمارت EDMS *لدعم* الضوابط المتماشية مع ISO 27001 و SOC 2 و GDPR و HIPAA والقانون رقم 18-07. وهو **لا** يدّعي أي شهادة أو اعتماد رسمي. تحقيق الامتثال الرسمي يتطلب تهيئة خاصة بالنشر، وتحصين البنية التحتية، وتدقيقاً خارجياً.

## الجذور والمعايير

<div dir="rtl" align="center">

**صُنع في الجزائر — يخدم العالم**

</div>

سمارت EDMS هو **مشروع جزائري**، صُمِّم وهُندِس ليُطابق المعايير الدولية. يحمل النظام تقليداً عريقاً من الحرفية الدقيقة — الاهتمام ذاته بالتفاصيل الذي شكَّل لعصور مدن الجزائر وقسنطينة وتلمسان — ويطبّقه على هندسة البرمجيات الحديثة. النتيجة منصة لا تختار بين الهوية المحلية والطموح العالمي: بل تسعى لكليهما، عن قصد.

البنية ونموذج التهديد ومجموعة الضوابط صُمِّمت في الجزائر وقُوِّمت مقارنةً بأكثر أطر الامتثال الدولية صرامةً. كل عنصر تشفيري (Argon2id، AES-256-GCM، HMAC-SHA256، TOTP وفق RFC 6238)، وكل سجل تدقيق (سلسلة SHA-256، إلحاقية فقط)، وكل قاعدة من قواعد أمان المدفوعات الاثنتي عشرة (نموذج ADR-016) يعكس ثقافة هندسية تتعامل مع الصرامة كحِرفة لا كقائمة تحقق.

### جدول المطابقة مع المعايير

المنصة *مصمَّمة لدعم* الضوابط المتماشية مع:

| الإطار | النطاق | المنشأ |
|--------|--------|--------|
| **ISO/IEC 27001** | أنظمة إدارة أمن المعلومات (ISMS) | دولي (ISO/IEC) |
| **SOC 2** | معايير الخدمات الموثوقة — الأمان، التوافر، السرية | دولي (AICPA) |
| **GDPR** | حماية الأشخاص الطبيعيين في معالجة البيانات الشخصية | الاتحاد الأوروبي |
| **HIPAA** | معلومات الصحة المحمية في السياقات الصحية | الولايات المتحدة |
| **القانون رقم 18-07** | حماية الأشخاص الطبيعيين في معالجة المعطيات الشخصية | الجزائر (10 يونيو 2018) |
| **إشراف ARPDD** | الامتثال للهيئة الوطنية لحماية البيانات | الجزائر (ARPDD) |

> *جزائري الأصل. دولي المعيار. عالمي التصميم.*

### دورة حياة الطلب

```
المتصفح → TLS → الوسيطة (CSP، كوكي المستأجر، ترويسات الأمان)
            → createApiHandler
                 → مصادقة (NextAuth JWT)
                 → حل المستأجر (كوكي / نطاق فرعي / تجاوز مشرف المنصة)
                 → فحص تحديد المعدل (نافذة منزلقة بـ Redis)
                 → تفويض (صلاحية RBAC + سياسة ABAC)
                 → تنفيذ المعالج (استعلام Prisma، محدد النطاق بالمستأجر)
                 → تسجيل التدقيق (سماح / رفض / خطأ، بسلسلة تجزئة)
            → مغلف JSON موحَّد { data | error: { code, message } }
```

## الميزات الرئيسية

### منصة SaaS متعددة المستأجرين

- **دورة حياة المستأجر** — إنشاء، تعليق، تفعيل، حذف مع سجل تدقيق كامل
- **موقع تسويقي عام** على `/` بأسلوب زجاجي متميز (البطل، الميزات، الأسعار، أبرز الأمان)
- **تسجيل ذاتي للعملاء** على `/signup` — محمي بـ honeypot، محدد المعدل، مُتحقَّق من البريد
- **طبقة مشرف المنصة** — دور `PLATFORM_ADMIN` برؤية شاملة عبر المستأجرين عبر تجاوز `?tenantId=`
- **تهيئة لكل مستأجر** — التصنيفات، جداول الاحتفاظ، السياسات، الاشتراك/إلغاء الـ AI، مزوّدو SSO

### الهوية والوصول

- **مصادقة كلمة المرور** — Argon2id (memoryCost 19 MiB، موصى به من OWASP)، سياسة 12 حرفاً، قفل بعد 5 محاولات
- **MFA** — TOTP (RFC 6238) مع حماية من إعادة التشغيل، أسرار مشفَّرة بـ AES-256-GCM، رموز احتياطية مُجزَّأة بـ SHA-256
- **مصادقة تصعيدية (Step-up)** — رموز لـ 5 دقائق (مُجزَّأة SHA-256، آمنة ضد السباق) للإجراءات المميزة
- **SSO** — OIDC (PKCE S256) + SAML (`wantAssertionsSigned`، انحراف ساعة دقيقة واحدة)، قائمة بريد مسموحة لـ JIT
- **مفاتيح المرور / WebAuthn** — `userVerification: 'required'`، قائمة AAGUID المسموحة، مخزن تحديات بـ Redis
- **الجلسات** — JWT (8 ساعات)، `httpOnly` + `sameSite=lax` + بادئة `__Secure-` في الإنتاج، قائمة سوداء لكل JWT + إلغاء جماعي
- **قفل الحساب** — يُطبَّق على مسارات كلمة المرور وSSO ومفاتيح المرور

### التفويض (RBAC + ABAC)

- **ستة أدوار نظام** — `tenant_admin`، `records_manager`، `security_officer`، `compliance_auditor`، `end_user`، `viewer`
- **أدوار مخصصة** — صلاحيات `domain:action` دقيقة مع دعم البدل
- **سياسات ABAC** — سماح/رفض بترتيب أولوية وشروط سياقية
- **تطبيق على الخادم في كل مسار** — إخفاء الواجهة ليس الضابط الوحيد أبداً
- **كل قرار مُسجَّل تدقيقياً** — السماح والرفض مع أثر تقييم السياسة

### دورة حياة الوثيقة

- **الرفع** — تحقق MIME بأجزاء سحرية (دفاع ضد التزييف)، رفع TUS قابل للاستئناف، S3 متعدد الأجزاء
- **الإصدارات** — تاريخ غير قابل للتغيير، تجزئات SHA-256 + SHA-1 لكل إصدار
- **القفل/الفتح** — مع سبب + تدقيق
- **الحذف الناعم** — يحافظ على سلسلة التدقيق
- **إعلان السجل** — السجلات الرسمية لا يمكن حذفها
- **جداول الاحتفاظ** — إجراءات حذف/أرشفة/مراجعة قابلة للتهيئة
- **الحجز القانوني** — يتجاوز الاحتفاظ، يمنع الحذف وتخفيض التصنيف
- **سجلات التصرف** — سجل رسمي للإتلاف بسلسلة عهدة كاملة

### التصنيف والحساسية

- **خمسة مستويات افتراضية** — عام، داخلي، سرّي، مقيَّد، حساس جداً
- **لافتات بصرية** — ملوَّنة حسب الحساسية في الواجهة
- **ضوابط التخفيض** — تتطلب صلاحية مرتفعة + مبرر، ممنوعة تحت الحجز القانوني
- **تاريخ كامل للتغييرات** — كل تغيير تصنيف مُسجَّل تدقيقياً مع الفرق
- **تصنيف محلي** — التصنيفات مترجمة لكل مستأجر لكل لغة

### سجل تدقيق مقاوم للتلاعب

- **إلحاقي في طبقة التطبيق** — مُعزَّز بمنح DB في الإنتاج
- **أرقام تسلسلية رتيبة لكل مستأجر**
- **سلسلة تجزئة SHA-256** — `eventHash = SHA-256(canonical_event || prevHash)`
- **تحقق السلامة بنقرة واحدة** — يجتاز السلسلة كاملةً، يُعلِّم أي تلاعب
- **تصدير CSV** — محدد المعدل ومُسجَّل تدقيقياً
- **يغطي** — المصادقة، التفويض، CRUD الوثائق، التنزيلات، المشاركة، التصنيفات، إجراءات الإدارة، اقتراحات الـ AI، المدفوعات

### سير العمل والموافقات

- **موافقات متعددة الخطوات تتابعية/متوازية** مع تفويض وخطافات تصعيد
- **تواقيع الموافقة** — إثبات SHA-256 لكل موافق
- **منطق إكمال الخطوة** — أي/كل الموافقين
- **إعلان السجل التلقائي** عند إكمال الموافقة
- **تحكم مزدوج** — العمليات الحساسة تتطلب موافقَين مستقلَّين

### المشاركة الآمنة

- **روابط موقَّعة محدودة زمنياً** — HMAC-SHA256، انتهاء 60 ثانية افتراضياً
- **حماية بكلمة مرور اختيارية** — Argon2id
- **حدود عدد المشاهدات** وعلامة مائية ديناميكية (المستلم + الطابع الزمني + الرمز)
- **إلغاء + أثر تدقيق كامل**
- **مُطبَّق بالسياسة** — ممنوع للتصنيفات المقيَّدة / الحساسة جداً

### ذكاء اصطناعي مساعد (إشراف بشري)

- **اقتراحات التصنيف** — محرك استدلالي + تراجع LLM
- **كشف PII / الكلمات المفتاحية** مع درجة ثقة
- **الـ AI لا يتصرف صامتاً أبداً**: تخفيض التصنيف، الحذف، رفع الحجز القانوني، توسيع الصلاحيات، تصدير المحتوى المقيَّد
- **كل إجراءات الـ AI مُسجَّلة** مع نسب المصدر
- **إلغاء اشتراك على مستوى المستأجر** عبر أعلام الميزات
- **خط أنابيب OCR** — تنقيط pdfjs-dist، تتبع الثقة، كشف اللغة franc

### التعاون والبحث

- **تحرير مشترك فوري** — Hocuspocus + Yjs + TipTap
- **حضور حي** — مؤشرات المتعاونين واختياراتهم
- **تعليقات** — مثبَّتة على مواضع الوثيقة
- **بحث دلالي OpenSearch** — تضمينات متجهة + نص كامل، واعٍ بالصلاحيات
- **عمليات بحث محفوظة** — استعلامات قابلة لإعادة الاستخدام لكل مستخدم مع تنبيهات

### الفوترة والمدفوعات

- **Stripe** — مدفوعات البطاقات، Checkout، إدارة الاشتراكات، تسوية الـ webhooks
- **NowPayments** — مدفوعات العملات الرقمية (BTC، ETH، USDT، و50+ أصولاً)
- **نموذج أمان مدفوعات من 12 قاعدة** — انعدام ثقة العميل، الذرية، تحقق HMAC للـ webhooks، منطق الأعمال في الـ webhook فقط، قائمة IP المسموحة، حماية من إعادة التشغيل، انتقالات الحالة الذرية، حماية من الدفع الناقص، تسوية cron، انتهاء الفاتورة، سلامة الاسترجاع، أثر التدقيق
- **دورة حياة الفاتورة** — توليد، دفع، تسوية، انتهاء، استرجاع — كلها مُسجَّلة
- **مستويات الاشتراك** — إدارة خطة لكل مستأجر مع تطبيق الحصص

### وحدة تحكم الإدارة

- **إدارة المستخدمين** — إنشاء، تعليق، تعيين دور، إعادة تعيين MFA
- **إدارة الأدوار** — أدوار مخصصة + منتقي صلاحيات
- **إدارة السياسات** — محرر قواعد ABAC بترتيب الأولوية
- **محرر تصنيف الضرائب** مع التوطين
- **محرر جدول الاحتفاظ** وإدارة الحجز القانوني
- **عارض التدقيق** مع تحقق سلسلة التجزئة
- **مراقب طوابير المهام** (BullMQ) ورؤية مشرف المنصة عبر المستأجرين

### الأمان والبنية التحتية

- **جاهز لـ TLS** — يُنهى عند الوكيل العكسي / البيئة المستضافة؛ HSTS مُفعَّل تلقائياً
- **CSP صارم**، `X-Frame-Options: DENY`، HSTS، `Referrer-Policy`، `X-Content-Type-Options`
- **كوكيز `httpOnly`، `sameSite=lax`، آمنة** في الإنتاج
- **لا أسرار في حزم العميل** — كل العمليات الحساسة على الخادم
- **حماية من اجتياز المسار** في طبقة التخزين
- **قائمة أنواع ملفات مسموحة + تحقق الأجزاء السحرية**
- **تثبيت DNS لـ SSRF** (undici) لكل الطلبات الصادرة
- **تشفير مغلف AES-256-GCM** للأسرار أثناء التخزين، دعم التدمير التشفيري
- **فحص ClamAV للبرمجيات الخبيثة** مع تراجع استدلالي
- **حماية CSRF** عبر NextAuth
- **إشعارات دفع المتصفح** (Web Push API)

## النشر

### Docker (موصى به للإنتاج)

ينتج `Dockerfile` متعدد المراحل صورة standalone مصغَّرة:

- **مستخدم غير root** — التطبيق لا يعمل كـ root أبداً
- **فحص الصحة** — يضرب `/api/health` كل 30 ثانية
- **undici مضمَّن** — تثبيت DNS لـ SSRF يأتي في الصورة
- **توليد أيقونات PWA** — يحدث وقت البناء عبر `sharp`
- **standalone output** — لا `node_modules` في الصورة النهائية

```bash
# البناء
docker build -t smart-edms:1.0.0 .

# التشغيل (حاوية واحدة — اقرن بـ Postgres + Redis خارجيين)
docker run -p 3000:3000 \
  --env-file .env.production \
  smart-edms:1.0.0
```

للحزمة المحلية الكاملة (تطبيق + عامل + Postgres + Redis):

```bash
docker compose up -d
```

### Kubernetes

ستة ملفات بيان في `k8s/` تغطي نشراً إنتاجياً:

| الملف | الغرض |
|------|---------|
| `namespace.yaml` | namespace مخصص `smart-edms` |
| `configmap.yaml` | تهيئة غير سرية |
| `secret.yaml` | قالب sealed-secret (استبدل بمدير أسرارك) |
| `app.yaml` | Deployment + Service + HPA (ويب + عامل) |
| `infrastructure.yaml` | Postgres StatefulSet + Redis StatefulSet |
| `cronjobs.yaml` | تصعيد سير العمل + تسوية الفوترة |

انظر **`k8s/README.md`** لترتيب `kubectl apply` وملاحظات دخول TLS.

### قائمة فحص الإنتاج

1. **قاعدة البيانات** — بدِّل `DATABASE_URL` إلى PostgreSQL؛ طبق سياسات RLS من `scripts/rls-policies.sql`.
2. **التخزين** — اضبط `STORAGE_DRIVER=s3` وتهيئة اعتمادات S3 / MinIO / R2. فعِّل إصدار الحاوية.
3. **الأسرار** — اضبط `NEXTAUTH_SECRET` و`SMART_EDMS_KEK` (32 بايت سداسياً/base64) عبر مدير أسرارك (Vault، AWS SM، GCP SM). KEK القرص المُولَّد تلقائياً **للتطوير فقط**.
4. **TLS** — أنهِ TLS عند موازن الحمل؛ HSTS مُفعَّل تلقائياً في الإنتاج.
5. **النسخ الاحتياطي** — فعِّل استعادة Postgres في نقطة زمنية + إصدار التخزين الكائني. شغِّل `scripts/backup.sh` وفق جدول.
6. **المراقبة** — وجِّه السجلات إلى SIEM؛ نبه على ارتفاعات `result=deny` وإخفاقات `audit.verify`. اربط Sentry DSN لتتبع الأخطاء.
7. **حدود المعدل** — اضبط حدود Redis لكل مسار في `src/lib/security/`.
8. **ClamAV** — وجِّه `CLAMAV_HOST` إلى daemon لـ ClamAV لفحص البرمجيات الخبيثة (تراجع استدلالي إذا لم يُضبط).

## وضعية الأمان

خضع سمارت EDMS لمراجعة أمنية شاملة. **أكثر من 125 ثغرة** تمت معالجتها عبر خمسة مستويات خطورة:

| الخطورة | العدد | الحالة |
|----------|-------|--------|
| حرجة | 9 | كلها مُعالَجة |
| عالية | 15 | كلها مُعالَجة |
| متوسطة | 63 | كلها مُعالَجة |
| منخفضة | 38 | كلها مُعالَجة |
| بنية تحتية | 5 | مُعالَجة (مع تحصين خبير) |

### أبرز النقاط

- **9 إصلاحات حرجة** — تجاوز المصادقة، تصعيد الامتيازات، تلاعب سجل التدقيق، SSRF، اجتياز المسار، تزوير التوقيع، هجمات إعادة التشغيل، إزالة التسلسل غير الآمنة، تعرض KEK
- **نموذج أمان مدفوعات من 12 قاعدة** — انعدام ثقة العميل، الذرية، تحقق HMAC للـ webhooks، منطق الأعمال في الـ webhook فقط، قائمة IP المسموحة، حماية من إعادة التشغيل، انتقالات الحالة الذرية، حماية من الدفع الناقص، تسوية cron، انتهاء الفاتورة، سلامة الاسترجاع، أثر التدقيق
- **تشفير مغلف AES-256-GCM** لكل الأسرار أثناء التخزين (أسرار MFA، أسرار عميل SSO، رموز احتياطية، رموز تصعيد) مع دعم تدوير KEK والتدمير التشفيري
- **تثبيت DNS لـ SSRF** عبر `undici` — كل طلب HTTP صادر يحل مرة واحدة ويثبّت IP للاتصال
- **سجل تدقيق بسلسلة تجزئة** — إلحاقي، سلسلة SHA-256، تحقق سلامة بنقرة واحدة، تصدير CSV محدد المعدل ومُسجَّل
- **MFA محمي من إعادة التشغيل** — `mfaLastTimestep` وفق RFC 6238 §5.2
- **رموز تصعيد آمنة ضد السباق** — `updateMany WHERE usedAt=null` ذرية تمنع إعادة استخدام الرمز
- **قفل الحساب على كل مسارات الدخول** — كلمة المرور، SSO، ومفاتيح المرور (كانت تُتجاوز سابقاً على SSO/passkey)

التفاصيل الكاملة في **[`docs/SECURITY.md`](docs/SECURITY.md)** و16 ADR في **[`docs/adr/`](docs/adr/)**.

### ملاحظات أمنية للمشغلين

1. **بدِّل كلمة مرور المشرف المبذورة** فوراً بعد أول تسجيل دخول.
2. **اضبط `SMART_EDMS_KEK`** إلى قيمة 32 بايت من KMS / `openssl rand -hex 32`. مفتاح القرص المُولَّد تلقائياً **للتطوير فقط**.
3. **فعِّل MFA** على كل حسابات الإدارة (TOTP إلزامي لـ `tenant_admin` في الإنتاج).
4. **تهيئة الاحتفاظ بالنسخ الاحتياطي** — سجلات التدقيق إلحاقية ويجب الاحتفاظ بها وفق جدول امتثالك.
5. **راقب إخفاقات `audit.verify`** — تشير إلى تلاعب محتمل.
6. **قيِّد الشبكة الصادرة** لخادم التطبيق إلا للخدمات المطلوبة (DB، S3، IdP، مزوّدو الدفع).
7. **لا تسجِّل أجسام الطلبات** في بروكسيات الإنتاج — قد تحتوي على محتوى الوثائق.

## التدويل

سمارت EDMS مُدوَّل بالكامل بـ **next-intl**:

- **5 لغات** — الإنجليزية (`en`)، الفرنسية (`fr`)، العربية (`ar` — RTL)، الإسبانية (`es`)، الألمانية (`de`)
- **1,209 مفتاح لكل لغة** — كل سلسلة مواجهة للمستخدم تتدفق عبر استدعاءات `t()`
- **دعم RTL** — تخطيط العربية يستخدم خصائص CSS منطقية (`margin-inline-start`، إلخ) للمرآة الصحيحة
- **جمع ICU** — مترجم الخادم يتعامل مع كل حالات ICU MessageFormat الحدية
- **تجاوزات لكل مستأجر** — يمكن للمستأجرين تخصيص الترجمات عبر وحدة تحكم الإدارة
- **ترجمة بمساعدة AI** — 943 مفتاحاً مترجماً عبر اللغات الأربع غير الإنجليزية مع مراجعة بشرية
- **كشف اللغة** — ترويسة `Accept-Language` + تجاوز الكوكي + بادئة URL

```bash
bun run check:translations    # التحقق من اكتمال المفاتيح عبر اللغات
```

## تطبيق ويب تقدمي

سمارت EDMS هو PWA قابل للتثبيت بالكامل:

- **بيان تطبيق ويب** — `manifest.webmanifest` مع الاسم، الأيقونات، لون المظهر، وضع العرض
- **Service Worker** — `sw-push.js` للاحتفاظ بعدم الاتصال + تسليم إشعارات الدفع
- **5 أيقونات تطبيق** — 192px، 512px، maskable 512px، apple-touch-icon، badge-72px (مُولَّدة عبر `sharp`)
- **صفحة عدم الاتصال** — احتياطي رشيق على `/offline` عند عدم توفر الشبكة
- **إطار العرض** — `viewportFit=cover` لدعم الشق / المنطقة الآمنة
- **قابل للتثبيت** — يلبي معايير قابلية التثبيت في Chrome / Edge / Safari
- **إشعارات الدفع** — تكامل Web Push API مع مفاتيح VAPID

## ما هذا النظام ليس عليه

- **ليس مزوّد توقيع إلكتروني مؤهل** — تواقيع أثر تدقيق أساسية فقط؛ استخدم خدمة توقيع مؤهل للتوقيعات الملزمة قانونياً.
- **ليس معتمداً أو مُعتمَداً لأي معيار** — الضوابط *متماشية مع* ISO 27001 / SOC 2 / GDPR / HIPAA / القانون 18-07، *ليست معتمدة لها*. تحقيق الامتثال الرسمي يتطلب تحصين نشر خاص وتدقيق خارجي.
- **ليس مصمَّماً للمواد الحكومية المصنَّفة** في بيئات غير معتمدة.
- **ليس بديلاً عن عملية استجابة لحوادث تنظيمية** — سمارت EDMS يوفر الكشف والتدقيق؛ الاستجابة مسؤولية فريقك.
- **ليس غير قابل للتغيير في طبقة قاعدة البيانات** — عدم القابلية للتغيير في طبقة التطبيق يجب تعزيزها بمنح DB وPostgreSQL RLS في الإنتاج.
- **ليس معالج مدفوعات** — سمارت EDMS يتكامل مع Stripe وNowPayments؛ نطاق PCI يبقى مع تلك المزوّدين. لا تخزِّن أبداً أرقام بطاقات كاملة.
