## Overview

Smart EDMS implements the functional requirements of **DoD 5015.02-STD**
(Electronic Records Management Software Applications Design Criteria
Standard) — the de facto standard for records management software in
government, defense, and regulated industries.

## Features

### File plan hierarchy
- Record categories with parent/child relationships (infinite depth)
- Each category has: code, name, disposition (permanent/temporary/unscheduled), retention schedule, vital flag
- DoD requirement mapping per category

### Folder lifecycle
```
open → cutoff → disposed
                ├── destroyed
                └── transferred
```
- Legal hold blocks disposition (checked before dispose)
- Step-up auth required for cutoff and dispose actions
- Disposition records created for audit trail

### Vital records
- Three types: **essential** (priority 1), **important** (priority 2-3), **useful** (priority 4-5)
- Four reasons: operational, legal, financial, historical
- Review cycles (default 12 months) with due-for-review dashboard
- Backup verification tracking

### Disposition authorities
- Four types: NARA GRS, NARA SF, agency-specific, court orders
- Retention instructions as JSON (active years, semi-active years, disposition action)
- Approval workflow (approvedBy, approvedAt)

### Compliance reporting
- JSON compliance report endpoint (`/api/records/compliance-report`)
- All 15 DoD requirements with implementation status and evidence
- Summary statistics (categories, folders, vital records, authorities)

## UI

- **Admin → Records Management** — dashboard with compliance status + category list
- **Folders page** — folder list with cutoff/dispose actions
- **Vital Records page** — vital record list with verify backup + due-for-review
- **Authorities page** — disposition authority management

## Important Note on Certification

This implementation provides the **functional requirements** of DoD 5015.02.
Formal **certification** requires an external audit by the U.S. Department of
Defense — this implementation does not claim certification. See the
[compliance posture statement](../README.md#roots--standards) for details.
